Search

search/simulated_annealing.hpp

Simulated Annealing

LOCAL SEARCH

悪化moveを温度依存確率で受理し、局所最適を越える。Stateを隠さず、差分評価のhot loopを問題側に残す。

向く 完成解＋軽い局所変更1反復 propose + delta + apply重要 近傍 / delta検証
アルゴリズム

最大化では delta = new − current。改善は常に受理し、悪化は exp(delta / T) で受理する。線形・指数schedule、iteration/time progress、reheat、adaptive近傍を提供する。

最小コード
ht::Annealer sa({100.0, 0.1,
  ht::CoolingSchedule::Exponential,
  ht::Objective::Maximize}, seed);

Move m = propose(state, sa.rng());
double delta = calc_delta(state, m);
if (sa.accept(delta, timer.progress())) {
  apply(state, m);
  score += delta;
}
注意
  • full_score == incremental_score をrandomized testする。
  • 温度調整より先に、近傍のfeasible率・受理率・改善/秒を見る。
  • 真scoreとsurrogateを分ける場合、bestは真scoreでも保持する。

search/hill_climbing.hpp

Hill Climbing

BASELINE

delta ≥ 0 のmoveだけを採用する。近傍と差分計算をdebugする最小baseline。

向く SA導入前弱点 局所最適目的 正しさ確認
使用例
State best = ht::hill_climb<State, Move>(
  initial, 1'000'000, seed,
  propose, delta_score, apply);

最大化用。最小化はscoreの符号を反転するか、問題側で同じloopを直接書く。

search/beam_search.hpp

Normal Beam Search

SEQUENTIAL

深さごとに全子を生成し、評価上位K個だけ残す。読みやすく、Stateが小さい問題の第一候補。

選択 nth_element重複 64-bit hashcost 候補数 × State copy
アルゴリズムと使用例
Node answer = ht::layered_beam_search(
  initial, depth,
  {.width = 500, .deduplicate = true},
  [](const Node& parent, auto emit) {
    for (Action a : actions(parent.state)) {
      Node child = parent;
      apply(child.state, a);
      emit(std::move(child));
    }
  });
木上Beamへ移るサイン

sizeof(State) × generated candidates が大きく、profileでcopyが支配的。Actionが小さく、applyとundoをO(1)前後で書ける場合。

search/tree_beam_search.hpp

Tree / Euler-tour Beam Search

COPY-FREE

候補履歴が張る部分木だけをEuler tourで保持し、1個のStateをapply/undoで全葉へ移動する。

State 1個保存 小さいAction tree結果 action列を復元
最小コード
ht::TreeBeamSearch<State, Action, long long> beam({
  .width = 5000,
  .deduplicate = true,
});

auto result = beam.solve(
  initial, initial_score, initial_hash, depth,
  [](State& s, auto emit) {
    for (Action a : enumerate_actions(s))
      emit(a, s.score + delta(s, a), next_hash(s, a));
  },
  [](State& s, const Action& a) { apply(s, a); },
  [](State& s, const Action& a) { undo(s, a); });
契約と危険点
  • expand はStateを変更せずにreturnする。
  • undo はbit単位で元状態へ戻す。apply/undo回数とfull scoreをtestする。
  • Actionへ大きいsnapshotを持たせると利点が消える。
  • prefix共有が少ない木、undoが重い状態では通常Beamとも比較する。

search/chokudai_search.hpp

Chokudai Search

LAYER QUEUES

深さごとのpriority queueを残し、浅い層から複数sweepする。通常Beamが一度で捨てる候補を後から展開できる。

向く 深さごとの候補品質が不均一memory 各層queue
使用例
Node answer = ht::chokudai_search(
  initial, max_depth, sweeps, width,
  [](const Node& node, auto emit) {
    for (Node child : expand(node)) emit(std::move(child));
  });

Node::operator< は良いnodeがpriority queueのtopになるよう定義する。

search/mcts.hpp

Monte Carlo Tree Search

ROLLOUT

selection → expansion → rollout → backpropagation。UCB1、PUCT、progressive wideningを切替可能。

向く rolloutに予測力弱点 巨大分岐 / 長いhorizonbaseline State copy型
Model API
struct Model {
  vector<Action> actions(const State&);
  State next(const State&, Action);
  bool terminal(const State&);
  double evaluate(const State&);
  double prior(const State&, Action);
  Action rollout_action(const State&,
    const vector<Action>&, ht::Xoshiro256StarStar&);
};
選ばない条件

rolloutがnoise、遷移copyが重い、決定論的で途中評価が強い場合はBeamを先に試す。transpositionはcycle、手番視点、depth依存価値を確認して問題側で統合する。

Random & Time

random/rng.hpp

Xoshiro256** RNG

HOT LOOP

SplitMix64でseedを拡散し、xoshiro256**で高速な64-bit乱数を生成する。bounded整数はrejectionでmod biasを避ける。

state 256 bit再現 同一seed用途 非暗号
API
ht::Xoshiro256StarStar rng(seed);
uint64_t raw = rng();
int i = rng.uniform_int(0, n - 1);
uint64_t k = rng.uniform_u64(n);
double x = rng.uniform01();
bool hit = rng.bernoulli(0.2);

timer/timer.hpp

Timer

TIME CONTROL

steady_clockとsafety marginを持ち、clock取得を256反復に1回などへ間引く。

cached elapsed / progressexact elapsed_exact
API
ht::Timer timer(1.95, 0.03);
for (uint64_t iter = 0; ; ++iter) {
  if (timer.poll(iter, 255)) break;
  double progress = timer.progress();
}

間引き区間の超過、初期化、出力時間をsafety marginに含める。

FastSet

DENSE / SPARSE

密な整数universe `[0,n)` のinsert / erase / contains / clearをO(1)。iteration順は不定。

使用例
ht::FastSet active(n);
active.insert(v); active.erase(v);

structures/rollback.hpp

UndoLog

REVERSIBLE

変更前のaddress/valueをstackへ積み、checkpointまでLIFOで戻す。

使用例
ht::UndoLog<int> undo;
auto cp = undo.checkpoint();
undo.assign(state.x, 10);
undo.assign(state.y, 20);
undo.rollback(cp);

記録中にvector resize等でaddressを無効化しない。

structures/zobrist_hash.hpp

Zobrist Hash

O(1) UPDATE

各(position,value)の乱数をXORし、1箇所変更時にold/newだけでhashを更新する。

使用例
ht::ZobristTable z(positions, values, seed);
hash ^= z.at(position, state[position]);
z.change(hash, position, old_value, new_value);

64-bit衝突は低確率であり、0ではない。誤除去不可なら二重hashかState追加照合。

structures/bitset_tools.hpp

Bitset Tools

WORD PARALLEL

vector<uint64_t> のpopcountとintersection count。計算量はword数。

使用例
a[v >> 6] |= 1ULL << (v & 63);
int all = ht::popcount(a);
int common = ht::intersection_count(a, b);

固定長ならまず std::bitset<N> を使う。

graph/dsu.hpp

DSU / RollbackDSU

CONNECTIVITY

通常DSUはpath compression＋union by size。rollback版はpath compressionを避け、merge履歴を戻す。

DSU 償却ほぼO(1)rollback O(log n) depth
使用例
ht::RollbackDSU dsu(n);
auto cp = dsu.checkpoint();
dsu.merge(a, b);
bool same = dsu.same(a, b);
dsu.rollback(cp);

graph/shortest_path.hpp

Multi-source BFS / Dijkstra

DISTANCE

非重み付きはBFS、非負整数重みはbinary-heap Dijkstra。AHC hot loopではworkspace再利用へ改造する。

使用例
auto d1 = ht::bfs(graph, vector<int>{s1, s2});
auto d2 = ht::dijkstra(weighted_graph, source);

BFSはO(V+E)、DijkstraはO((V+E) log V)。0/1重みなら0-1 BFSを選ぶ。

grid/grid.hpp

GridIndex

FLATTEN

id = r*w+c で2D gridを連続memoryへ置き、4近傍と境界判定を共通化する。

使用例
ht::GridIndex grid{h, w};
int v = grid.id(r, c);
for (int d = 0; d < 4; ++d) {
  int nr = r + grid.dr[d], nc = c + grid.dc[d];
  if (grid.inside(nr, nc)) visit(grid.id(nr, nc));
}
