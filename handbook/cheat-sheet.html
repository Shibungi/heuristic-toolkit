AHC Contest Cheat Sheet

最初の30分

  1. 規約・I/O・0点条件
  2. score式を紙に分解
  3. 手計算↔scorer照合
  4. 最小feasible出力
  5. greedy baseline
  6. 10→100 seed保存
  7. profileと反復数
  8. delta可能性・依存範囲

探索の初手

  • 完成解を局所変更 → HC/SA
  • 逐次構築 → Beam
  • 深さ別に候補偏る → Chokudai
  • rolloutに予測力 → MCTS候補
  • 強制約 → feasible表現 / repair
  • 巨大 → block / coarse-to-fine

SAを始める

  • swap / relocateを1つずつ
  • full == incremental randomized test
  • 時間帯別accept率
  • 序盤悪化を受理、終盤HC
  • bestは真scoreで別保持
  • 近傍別 改善/秒

改善が止まった

  1. delta bug
  2. 表現の到達可能性
  3. 弱/強近傍
  4. 評価関数の順位相関
  5. 反復数bottleneck
  6. initial multi-start
  7. destroy-repair
  8. 時間帯で探索対象を変更

Beamが遅い

  • State bytes × nodes
  • sort → nth_element
  • parent/action保持
  • 差分hash・dedupeの価値
  • 候補上位K
  • workspace再利用
  • depth別width

計測

  • score: 並列throughput
  • time: 単独＋affinity＋warmup
  • A/B: 同一seed paired
  • mean/median/W-T-L/CI
  • 100で方向、1000で確認
  • holdout seedを残す
  • quality × iterations/sec

終了30分前

  • release buildで再検証
  • assert/log無効
  • safety margin確認
  • 最大入力・corner・timeout
  • 出力validator
  • best stateを出しているか
  • seed固定/非固定を判断
  • 提出source単体compile

危険信号

  • full scoreを毎move
  • State大量copy
  • 全候補sort
  • unordered_mapがhot
  • 並列時間を提出時間扱い
  • 少数seedの平均だけ
  • 賢い評価で反復1/10
  • 複雑化後にbaseline未比較

記録する数字

  • best/current score
  • iterations/sec
  • 近傍別trial/accept/improve
  • score breakdown
  • wall median/p25/p75/CV
  • seed別relative score
  • compile mode / git diff
